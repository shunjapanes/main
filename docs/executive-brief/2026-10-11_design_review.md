# Executive Morning Brief HTML記事化 設計・実装レビュー

- 作成: 2026-10-11 / Claude Code
- 状態: **設計案（未実装・未デプロイ・既存タスク未変更）**
- 対象: 毎朝06:00 JSTのChatGPTスケジュール「Executive Morning Brief」（以下EMB）
- 注意: このリポジトリは**公開リポジトリ**。本書には個人情報・ID・通知先などを書いていない。

---

## 0. 結論（先に読む）

1. **おすすめ構成は「Google Apps Script（GAS）の自分専用Webページ ＋ 既存ChatGPT 06:00は編集長兼通知役のまま」**。
   GASは「Googleアカウントにログインした本人しか開けないページ」を無料で作れる。個人のGmail・資産情報を扱うのに一番安全で手間が少ない。
2. **GitHub Pagesは個人情報には使わない**。このリポジトリは公開設定で、すでに1件フォーク（複製）されている。無料プランのPagesは誰でも見られる。
3. **Google Driveに置いたHTMLをスマホで開く方式は不向き**。DriveはHTMLをWebページとして表示せず、ソースかプレビュー表示になりリンクも安定しない。Driveは「保管庫」に使い、「読む場所」にはしない。
4. **ChatGPTのスケジュールタスクに「毎日HTMLファイルを確実に保存させる」のは現時点では不確実**。ファイル書き込みの可否・安定性は要検証（GPT Astra側の確認事項）。そのため設計は「ChatGPTが保存に失敗しても新聞は出る」形にする。
5. 中身は **「データ（JSON）」と「見た目（HTMLテンプレート）」を分ける**。AIは毎朝データだけ作り、見た目は毎日同じテンプレートで描く。デザイン崩れ・AIごとの差が出ない。

### SHUNの判断が必要なこと（1つだけ・最優先）

```
【お願い】05:30に「データ集めだけ」をするGASの時刻トリガー（自動実行の予約）を作ってよいか決めてください
【理由】06:00の新聞に最新データを載せるには、事前の自動収集が必要です（通知は出さず、ChatGPTの06:00配信とは重複しません）
【やらない場合】「ページを開いた瞬間に集める」方式になり、表示に10〜30秒かかり、開かなかった日の記事が残りません
【おすすめ】A：05:30のデータ収集のみ許可（PCのスリープの影響を受けず、確実に毎日残るため）
```

## 1. 推奨アーキテクチャ

### 1-1. 役割分担（誰が何をするか）

| 役割 | 担当 | 理由 |
|---|---|---|
| 通知（毎朝の「届いた」） | **既存ChatGPT 06:00（変更はリンク1行の追加のみ）** | 重複配信を作らない。音声会話（ジャービス）の読み上げ元もこのまま使える |
| 編集（30秒要約・ニュースの解説） | 既存ChatGPT 06:00 | 今の品質と運用ルールをそのまま活かす |
| データ収集（Gmail・Drive・株価・AI進捗） | **GAS（05:30、通知なし）** | Googleの中で動くのでPCが寝ていても動く。Gmail・Driveを本人権限で読める |
| 表示（新聞ページ） | **GAS Webアプリ（本人のみ閲覧）** | ログイン必須。URLが漏れても他人は見られない |
| 保管（日付別アーカイブ） | Google Drive（専用フォルダ） | 既存のMAIN運用と同じ場所で検索・引き継ぎができる |
| 正本（タスク・AI作業） | 既存 MAIN の `TASK_LEDGER.md` / `Task_Events/` | 既存ルールを尊重。新聞は**読むだけ**で書き換えない |

### 1-2. 構成図

```
[05:30 GAS 収集] ──読む──> Gmail(読取のみ) / Drive: TASK_LEDGER・Task_Events・DailyReport
      │                     / 株価(GOOGLEFINANCE等) / ニュースRSS見出し
      ▼
 Drive: Morning_Brief/data/2026/10/2026-10-11.json   ← その日の「材料」（正本はこれ）
      │
      ├──> [06:00 既存ChatGPT EMB] JSONと各種情報を読む → 30秒要約・解説を作成
      │        └─ 通知本文の末尾に「今日の朝刊」リンク1行（固定URL）
      │
      └──> [GAS Webアプリ] 開いた時にJSON＋テンプレートで描画（本人ログイン必須）
               └─ 初回表示時にHTMLの写し(snapshot)を archive/ に保存
```

- ChatGPTとページが**同じ05:30のJSONを見る**ので、チャットと新聞の数字が食い違わない。
- ChatGPTが書いた要約・解説をページに載せる方法は「段階2」で検証する（1-3参照）。

### 1-3. ChatGPTの文章をページに載せる方法（段階的）

| 段階 | 方法 | 状態 |
|---|---|---|
| 段階1 | ページの「Executive Summary」は**ルールで自動選出**（今日期限・承認待ち・大きな値動きの上位3件）。ニュース解説は**ChatGPTのチャットへのリンク**で読む | 確実にできる |
| 段階2 | ChatGPTが要約を `editorial/YYYY-MM-DD.json` としてDriveへ保存できるか検証。できればページに埋め込む | **要検証（GPT Astra確認事項）** |
| 段階2' | 保存できない場合の代替：GASからAI（API＝別のシステムへの頼みごとの窓口）で要約を作る | 月数十〜数百円程度。APIキーは「別管理」。AIが2系統になるので慎重に判断 |

## 3. HTML画面設計案（スマホ優先）

見本: [mock_morning_brief.html](mock_morning_brief.html)（**架空データ**。実データは入っていない）

### 3-1. 画面の並び（縦1列・上から重要順）

| # | 区画 | 表示内容 | 1タップで飛べる先 |
|---|---|---|---|
| 0 | 見出し帯 | 日付・号数・データ確認時刻・**全体状態（正常／一部未取得）** | 前日・翌日・過去記事一覧 |
| 1 | Executive Summary | 重要3件（1件1〜2行、色ラベル：要対応／注目／完了） | 該当の区画・元メール・元ファイル |
| 2 | Market & Portfolio | 主要指数（日経・TOPIX・S&P500・ドル円）→ 保有の合計・前日比 → 口座別（特定／NISA）→ 銘柄行 | 銘柄の外部情報ページ |
| 3 | News & Insights | 社会／経済／AI／モータースポーツの切替タブ。各記事：見出し・2行要約・**出典名・日付** | ニュース原文 |
| 4 | AI Project Tracker | 案件ごとのカード：担当AI・状態（作業済／検品済／業務反映済）・テスト結果・次の一手 | GitHubのPR・Driveの成果物 |
| 5 | Action Center | 返信待ち・期限・承認待ち・やり忘れ候補。期限が近い順 | Gmailのスレッド・Driveのファイル |
| 6 | Sources & Audit | 取得元一覧・取得時刻・**未取得の項目**・保存状況・版番号 | 元データJSON |

### 3-2. デザイン方針

- 色: 地はネイビー（`#0B1F3A`）、見出し帯と強調はブルー（`#1E5BD8` / `#3B82F6`）、本文面は白〜淡い青灰。上昇は緑・下落は赤（色だけに頼らず「▲▼」も併記）。
- 文字: 本文16px以上、数字は等幅数字（桁がそろう）。
- タップ: 押せる場所は高さ44px以上。区画ジャンプ用の固定メニューを画面下に置く（片手操作）。
- 「未取得」は**灰色の破線枠＋理由**で表示し、空欄や「問題なし」にしない（既存ルール「未取得を問題なしにしない」と同じ）。
- 金額の表示切替（目隠しボタン）：電車内などでのぞき見されないよう、初期表示で金額を伏せる設定を用意。
- 画像生成は使わない。グラフが必要な場合はHTML/SVGで描く（軽い・崩れない）。

## 4. データフロー

```
① 収集（05:30 GAS）
   Gmail ─ 検索条件で抽出（返信待ち・期限語・承認依頼・証券会社の約定通知）
   Drive ─ TASK_LEDGER.md / 未反映Task_Events / DailyReport.md / Board_Digest.md（前回版と明記）
   株価 ─ 指数・個別株（取引日を必ず付ける）
   投資信託 ─ 基準価額（取得元を要検証）
   ニュース ─ 指定媒体のRSS見出し＋URL＋公開日時
        │  各項目に「取得元・取得時刻・成否」を付ける
        ▼
② 整形（GAS）
   重複除去（メールIDやURLを鍵に）→ 期限順に並べる → 個人情報の最小化
   → data/YYYY/MM/YYYY-MM-DD.json（版番号付き）
        ▼
③ 編集（06:00 既存ChatGPT）
   JSONを読む＋自分の調査 → チャットに要約・解説 → 末尾に新聞リンク
        ▼
④ 表示（GAS Webアプリ）
   ?date=YYYY-MM-DD で日付指定。無指定は最新版
        ▼
⑤ 保存
   初回表示時に archive/YYYY/MM/YYYY-MM-DD.html を保存。index.json に1行追記
        ▼
⑥ 通知
   既存ChatGPT 06:00の通知のみ（新しい通知は作らない）
```

### 4-1. 保有資産の扱い（推測しない仕組み）

- 保有は「**取引の記録を積み上げて計算する**」方式（家計簿と同じ）。数量を直接書き換えない。
- 台帳はGoogleスプレッドシート1枚（列：日付／口座区分＝特定・NISA／銘柄／種別＝買付・売却・積立・分割／数量／単価／手数料／元メールID／**確認状態**）。
- 約定メールから**AIが行を「提案」→ SHUNが確認して「確定」**。確定前の行は計算に入れず「未確定 n件」と表示。
- 株式分割は「分割比率の行」を入れて数量・単価を自動補正。
- 取得原価が不明な銘柄は**評価損益を出さず「取得原価未確定」**と表示。
- 同じメールを2回取り込まないよう、元メールIDを重複チェックの鍵にする。

### 4-2. AI Project Trackerの判定

- 既存 `Task_Events` の `status_code` をそのまま使い、「作業済（未検品）」「検品済」「業務反映済」を**別の色で**表示（既存ルール：AI作業完了・検品完了・業務登録完了を区別）。
- 同じ `task_id` に複数AIの報告がある場合は1枚のカードにまとめ、報告が食い違えば「要確認」。
- 7日以上更新のない未完了は「止まっている可能性」として表示。

## 6. リスク・改善提案（実装前に解決すべき問題）

### 6-1. 必ず先に決めること

| # | 問題 | 提案 |
|---|---|---|
| 1 | ChatGPTタスクの保存能力が不明 | 段階0で検証。保存できなくても新聞は成立する設計にしてある |
| 2 | 05:30の自動収集を作るか（新しい自動実行になる） | 冒頭の【お願い】を参照。通知は出さないので配信の重複にはならない |
| 3 | 投資信託の基準価額の取得元 | 証券会社・運用会社の公開情報のどれを使うか決める。取れない日は前営業日値と明記 |
| 4 | Knowledge Updateの存廃 | 新聞は依存しない設計。存続なら「Sources & Audit」に成否を表示するだけ |

### 6-2. 安全・個人情報

- **公開場所に個人情報を置かない**: このリポジトリ（公開）・GitHub Pages・公開の通知チャンネルには、金額・メール内容・社内情報を出さない。
- **通知文は中身を書かない**: 既存の通知サービスは通知先名を知っていれば誰でも読める仕組みのため、通知を使う場合も「朝刊ができました」程度にする。
- **権限は最小限**: GASの権限は「Gmail読み取りのみ」「Drive読み取り＋新聞フォルダへの書き込みのみ」に絞る。メール送信・削除の権限は付けない。
- **メール内の指示は実行しない**: メール本文は「データ」として表示するだけ。画面表示時は必ず文字を無害化（エスケープ）し、リンクは `https://` のみ許可。
- **承認が必要な操作はしない**: ページには「開く」リンクだけを置き、返信・承認・売買のボタンは置かない。
- 社内情報: 会社のメールやデータを個人Googleで扱ってよいかは**要確認**（会社規程次第）。確認までは社内案件は「件名のみ・本文なし」で表示。

### 6-3. 失敗・重複への対策

| 事態 | 対策 |
|---|---|
| 一部データが取れない | その区画だけ「未取得（理由・時刻）」を表示し、他は出す。全体状態を見出し帯に表示 |
| JSON自体が作れない | ページは**前日版を表示＋赤帯「本日版未作成」**。ChatGPTは従来どおり配信されるので朝の情報は途切れない |
| 同じ日に2回実行された | ファイル名を日付で固定し、版番号（v1, v2）を付けて上書きではなく追記。表示は最新版、履歴は監査欄で確認 |
| 通知の重複 | 通知は既存ChatGPTのみ。GAS側は通知しない（構造的に重複しない） |
| 古いデータを今日のものと誤認 | 全項目に取得時刻。株価は取引日。前回版を使った項目は「前回版」ラベル |
| PCのスリープでMAINの同期が遅れる | Driveファイルの最終更新時刻を表示し、6時間以上古ければ警告 |

### 6-4. 過去記事の保存・検索・比較

- 正本は **JSON**（機械で比較できる）、HTMLは見るための写し。
- `index.json` に日付・重要3件の見出し・全体状態を1行ずつ追記 → 一覧画面と簡易検索に使う。
- 日付比較画面（段階4）：2つの日付を選ぶと、資産合計・未完了タスク数・承認待ち件数の差を表示。
- 全文検索はDriveの検索をそのまま使える（JSONもMarkdownも検索対象）。

### 6-5. 費用・保守・AI間の引き継ぎ

- 費用: GAS・Drive・スプレッドシートは無料枠内の見込み。ChatGPTは既存契約のまま。AGY（Antigravity）の利用枠は**使わない**（枠切れ障害の再発を避ける）。
- 保守: 直す場所は「収集スクリプト」「データの型（JSON定義）」「テンプレート」の3つだけ。
- 引き継ぎ: `Morning_Brief/README.md` に「データの型・保存場所・失敗時の見方・止め方」を書き、変更時は `Task_Events` に記録。どのAIでも同じJSONを読めば続きができる。

## 7. Claude Code と GPT Astra の観点

> 注: GPT Astra側の見解は本書では**代弁しない**。ChatGPT側の機能はClaude Codeからは確認できないため、GPT Astraに確認してほしい点として挙げる。

### Claude Code の評価（実装・運用の観点）

- 実現性: **高い**。GAS・Drive・Gmailの読み取りと、HTMLテンプレートの描画は標準的な技術で完結する。
- 最大の不確実性はChatGPT側（スケジュールタスクからのファイル保存）。だからこそ「ChatGPTは編集と通知」「保存と表示はGAS」と分け、ChatGPTの機能変更に左右されない形を推奨する。
- Claude Codeが担当できる範囲: テンプレート・GASコード・JSON定義の作成、自動テスト（表示崩れ・リンク切れの点検）、レビュー。

### GPT Astra に確認してほしいこと

1. スケジュールタスクの実行中に、Google Driveへ新規ファイルを**書き込める**か。毎日安定するか。
2. スケジュールタスクから、DriveのJSONを確実に**読める**か（読み取りの失敗率）。
3. 通知本文に固定URLを入れた場合、スマホ通知からワンタップで開けるか。
4. 1回の出力の長さ上限と、長いときに途中で切れる挙動。
5. プロンプトに「リンク1行追加」をしたとき、既存の音声用追加指示案（未反映）との整合。
